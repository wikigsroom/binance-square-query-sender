# 币安广场新闻与行情内容

> 此技能描述早期根目录批次工具，不是当前 Dashboard 平台 Worker。平台规则以根 `AGENTS.md`、已发布预设和保存的运行配置为准；不能用本技能的统一 200 字符或三币要求覆盖所有预设，也不能对平台正在调度的相同账号启动额外轮次。

复用已验证的内容制作与发布流程。技能包只包含操作规范和内容准备、校验脚本；认证资料由当前任务的外部发布运行环境处理。

## 工作范围

- 本项目所有命令和产物位于 `C:\dev\sandbox\binance square`；使用原生 Windows、Node.js，不调用 Docker、WSL 或其他本地虚拟化环境。
- 优先使用 HTTP 接口；使用浏览器时，完成后关闭本次操作中不再需要的标签页。
- 所有帖子正文必须由远程 `gpt-6-luna` 从零生成；禁止本地文案生成器、固定模板、模板片段或手工替代正文。模型密钥只从进程环境 `LUNA_API_KEY` 读取，缺少密钥、请求失败或返回内容不合规时停止本轮，不发送替代稿。
- 根据当前用户要求区分准备、预览与发布。明确要求发布且范围已确定时执行，不追加重复确认；创建、加载、测试技能本身不发帖。
- 每批每个目标账户一篇，独立内容；旧批已用过的账户可以参加用户明确要求的新批。新内容使用新任务 ID；重跑同批应跳过成功或结果不确定的提交。

## 内容与准备

先读 [references/writing.md](references/writing.md)。使用滚动24小时榜单：币安正在交易的现货 USDT 交易对，排除成交额为零的交易对，按涨跌幅排序。每篇从涨幅前五和跌幅前五合计选三个不同代币，两榜都选到；使用 `$代币` 标签。

每篇优先120—190字符，含标签、标点、空白、换行及正文链接总计不超过200个Unicode字符。写作优先级是事实、标签、新闻归因、自然中文、批内差异；围绕相关新闻、事件数据或行情写清一个具体关注点，分别交代三个代币的币安现货滚动24小时涨跌幅，表达第一人称散户观点和鲜明态度。用地道、顺口的聊天式口语、完整句子和自然分段；各篇独立构思，变化态度、叙述顺序、段落长度、标签位置与收尾，不固定段数或套用统一结构。正文禁止出现“情绪”“情感”“情绪化”“心态”“翻译腔”等元话语，也禁用“这让我……”“我更愿意……”“不能据此……”“至少我……”“我暂时把……”“真要让我……”等生硬套句。详细文风见 [references/writing.md](references/writing.md)。每轮也读取项目 `CONTENT_RULES.md` 中用户最新要求。配图从项目 `imagegen` 随机选一张。

优先核实区块律动（BlockBeats）近72小时与所选代币相关的新闻，取材和来源记录见 [references/news.md](references/news.md)。可以使用注明日期的近7天重要事件；没有可靠相关新闻时基于行情写。记录原文、报道与事件时间、事实摘要和使用的帖子，准确区分计划与已实施，不把新闻直接当作涨跌原因。

在项目目录执行，数量和账户别名来自本次确认的范围：

```powershell
node .\market.mjs
node .\.agents\skills\binance-square-posts\scripts\batch.mjs prepare --count 7
```

准备脚本只生成随机代币与图片规格，不生成正文。需要匹配现有发布运行环境的账户别名时，用 `--labels a,b,c` 代替 `--count`。

分别写出每篇，按规格 ID 将正文保存到项目内的 `drafts.json`。文件结构及完成方式见 [references/publishing.md](references/publishing.md)。

```powershell
node .\.agents\skills\binance-square-posts\scripts\batch.mjs finalize --batch batches/本批目录 --drafts batches/本批目录/drafts.json
```

校验三标签、榜单资格、200字符上限、图片、独立内容与风格重复提示；再通读整批，人工核对新闻来源、进展和三币涨跌幅数字。脚本的相似度提示辅助判断，不能代替对事实、语气、观点和格式的整体审阅。

## 发布与核验

需要实际发布时读 [references/publishing.md](references/publishing.md)。使用项目已有的 `square-batch.mjs` 与币安官方 `vendor/square-post/scripts/post-image.mjs` 完成上传、处理、发布，使用当前任务的外部账户映射，不把认证资料复制到本技能目录。

默认并发3个账户，各账户独立执行；一个失败继续处理其他账户。发布前确认行情不超过15分钟，否则刷新并重新确认所选代币资格及正文中的涨跌幅数字。完整保留每篇状态、新闻来源和发布回执。

接口明确成功且返回帖子 ID 后，调用 `verify-post.mjs` 或 `verify-batch.mjs` 读取线上帖子，核验正文、三个代币标签和一张图片。网络超时、504或缺少 ID 属于结果不确定，先核验线上状态，不自动重发。认证、内容或账户限制按接口原样记录，不绕过平台限制。

交付本批成功、失败、结果不确定及核验数量；提供对应帖子链接或本地报告。不把提交成功当作已核验通过。
