# 文件与发布衔接

内容准备脚本从项目内行情快照和 `imagegen` 读取公开素材，只接收数量或账户别名。内容清单包含 `rankings.json`、`specs.json`、`drafts.json`、`posts.json` 和校验结果；引用的新闻另存本批 `news.json`，格式见 [news.md](news.md)。技能包与内容准备脚本不含认证资料。

`drafts.json` 使用以下结构，ID与规格完全对应；正文由 Codex分别撰写：

```json
{
  "drafts": [
    { "id": "规格中的任务ID", "text": "本篇独立正文" }
  ]
}
```

`finalize` 将正文与规格合并为 `posts.json`，进行结构校验并输出 `validation.json`。它校验200字符上限、三标签、榜单资格、图片和内容差异；新闻事实、报道日期及正文涨跌幅数字仍需与本批来源和行情逐项核对。核对后，将本批清单交给当前任务已授权的外部发布运行环境。

本批报告附所用新闻的标题、日期和原文链接；没有引用新闻时注明依据行情撰写。正文链接与所有空白、标点、标签都计入200字符。

项目运行工具：

- `market.mjs`：刷新实时榜单，保存 `snapshots/rankings.json`。
- `square-batch.mjs`：默认只预览；`--send` 实际发布。`--posts` 指向本批清单，账户映射由外部运行环境指定。不能把账户资料、旧批账户文件或历史回执复制进技能包。
- `vendor/square-post/scripts/post-image.mjs`：币安官方图片上传、处理、发布程序，由批量工具调用。
- `verify-post.mjs 帖子ID`：读取线上正文、代币标签和图片，核验项目 `runs` 中对应任务。
- `verify-batch.mjs 本批目录`：核验指定批次并保存本批 `report.json`、`report.md`。指定批次目录，避免默认最近批次造成误读。

批次的账户别名必须与外部运行环境对应。一批同一目标只发送一篇，不同目标必须使用不同正文。发布前整体校验，执行时按账户隔离错误。保存新批ID与每篇回执，已经成功或结果不确定的任务不自动重复提交；更换文案属于新批，需要当前任务的发布范围涵盖它。

上传失败且尚未调用发布接口，可以在正常网络恢复后继续；发布接口超时或504时不能推断是否已生成帖子。先读取线上信息核对，不能仅凭官方脚本打印 `Success!` 就宣布核验通过。

没有可用的外部发布运行环境时，完成内容清单并说明缺少发布衔接；不要为了封装技能读取、搬运或创建认证资料。本技能加载与离线测试均不触发外部发布。
