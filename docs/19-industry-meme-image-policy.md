# 生图策略：只生成各行各业的 meme 梗图

生效要求：2026-10-22，用户明确要求“只允许生成：各行各业的 meme 梗图”。这是全局生图限制，适用于全部正文方向，不只是名称中带 Meme 的预设。

**2026-10-23 更新：当前十种预设全部改为只用已有图库，已发布 v3，不再逐篇生图。** 详见[当前预设与图库模式](14-ten-content-presets.md)。本页的生成策略仍适用于用户另行请求的生图；下方逐篇生成的升级与验收为 2026-10-22 历史记录。

## 允许的图与取材方式

每张新生成图片必须有清楚的笑点、吐槽或荒诞反差。可以使用简短、地道的中文梗字幕，也可以完全依靠角色表情、动作、道具和前后变化表达。禁止用没有梗点的普通资讯插画、抽象概念图、杂志封面或产品海报替代。

运行时从22类行业中随机选择一次场景，包括办公室、程序开发、餐饮、外卖快递、教育、医护、建筑装修、零售电商、农业、物流、制造、会计、设计、传媒、科研、酒店旅游、交通、健身、美发、游戏影视、法律和维修家政。不局限于币圈、狗狗、青蛙，也不要求每张图出现代币或K线。

另随机选择单格反应、双格反差、四格反转、拟人动物、荒诞摆拍或粗线涂鸦等表现形式。行业与形式在同一个任务中固定保存；容量等待及同任务重新执行不会重新抽签，避免实际请求与记录不一致。

## 执行位置

1. [十种预设配置](../app/content-presets/presets.json)统一使用行业梗图方向，保留各自正文要求。
2. [全局策略](../app/square-service/src/image-policy.ts)构造 `industry-meme-v1` 实际生图要求，把原提示词作为主题参考；冲突的旧插画要求需舍弃。
3. [图片任务服务](../app/square-service/src/media.ts)在创建任务时冻结行业和形式，在认领旧排队任务时补上新策略。已完成或结果不确定的任务不会因此自动重试。
4. [最终图片模型入口](../app/square-service/src/ai.ts)再次应用同一策略，覆盖手动任务、预设任务、旧预设创建的任务和直接适配器调用。
5. 任务与生成记录保存 `requestedPrompt`、实际 `prompt`、`imagePolicy.version`、行业及表现形式；生成记录仍包含真实请求、指定模型、提供方回执及文件来源。
6. Dashboard 的手动生图和预设编辑页面显示仅限行业梗图的说明。

这是对生图任务和实际请求的强制构造规则，尚未增加独立视觉模型评审，不能将提示词合规等同于逐张成品经人工确认。历史已生成图片与历史发布记录不重绘。

## 线上升级与核验

原生服务版本：`20261022-industry-memes`。先完成后端64项回归、前端类型检查及构建、十种配置解析。新增回归使用本地 HTTP 夹具检查最终请求，不调用付费图片模型、不发帖。

通过[预设升级脚本](../app/deployment/scripts/update-meme-image-policy.sh)发布十份新版本，只更新图片提示词、表现方向与图片标签。逐项比较正文规则摘要，保留尚未发布的正文草稿、模型参数、账号绑定、随机周期和运行设置。保存升级前快照；使用版本检查及幂等键，避免不确定状态下盲目重发。

服务切换在没有活跃发布或生图请求时进行；已准备但因活跃任务而暂缓切换的版本，必须再次与发布包核对文件摘要后才能继续。全程使用原生 Node.js、Python、PostgreSQL 与 systemd，不使用 Docker 或 WSL。

生产逐预设回读与保留设置检查见[策略升级报告](image-policy/production-report.json)。本轮没有额外请求付费样图；后续自动任务按新策略生成，其真实调用记录可在 Dashboard 中查看。
