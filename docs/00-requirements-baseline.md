# 00 · 需求来源、清洗结果与边界

版本：0.1；日期：2026-10-20。

## 原始需求记录

用户希望系统构建一个帮助管理多个个人币安广场账号的平台，包含完整的控制面板 Dashboard 和实现具体发送业务的后端。

1. 所有发送的文字必须使用 `gpt-6-luna` 等具体 AI 模型构建、编辑后才能发送。
2. 所有发送的图片必须来自本地已有图库，或新建的 `GPT Image 2` 生图任务。
3. Dashboard 管理全部个人币安广场 API Key。
4. Dashboard 管理经本系统发布的帖子列表，支持通过各项信息搜索、查询。
5. 支持多种内容风格预设，预设内容风格、方向、素材、数据源，以及文字长度、配图风格等约束。
6. 各账号有独立的随机发送周期，可分别设置发送间隔上下限，各账号遵循各自规则在不同时间发送。

补充确认：**远程服务器部署**；**每账号绑定多个预设，按权重随机选用**。

## 清洗后的核心对象

| 对象 | 业务含义 | 与其他对象的关系 |
| --- | --- | --- |
| 账号 Account | 一个真实的个人币安广场身份，使用稳定内部 ID | 凭据可以轮换，账号历史不随 Key 改变 |
| 凭据 Credential | 币安广场 Key 或模型服务凭据 | 由后端保管；模型凭据与广场凭据分别管理 |
| 内容预设 Preset | 可版本化的写作、取材、校验和配图规则 | 一账号多预设；每次任务固定一个预设版本 |
| 图片 Asset | 托管图库中的实体图片及来源信息 | 可供多个任务使用，保留每次使用记录 |
| 生图任务 Image Job | 一次指定图片模型的生成请求 | 成功后产生一个或多个 Asset；首版帖子默认使用一张 |
| 发布任务 Publication Job | 从取材、文字生成到发布、核验的完整执行单元 | 属于一个账号，锁定配置、文案版本和配图 |
| 帖子 Post | 发布任务关联的内容与远端发布结果 | 具有本地状态、远端 ID、链接和独立核验状态 |
| 调度 Schedule | 账号级的随机间隔规则和持久化下一次时间 | 与其他账号的调度状态独立 |

## 六项需求的规范表述

| 编号 | 规范需求 | 不能混淆的边界 |
| --- | --- | --- |
| R-01 | 只有具备有效 AI 成稿记录的最终文字版本才可提交发布 | UI 允许输入参考或修改要求；手动修改后的发送正文仍须经 AI 成稿 |
| R-02 | 每张发送图片都可追溯到已有图库或指定生图任务 | 远程部署时“本地图库”指服务器托管图库；电脑图片须上传或迁入 |
| R-03 | 管理多个账号、Key 轮换、启停、凭据健康和账号绑定 | 管理 Key 不是每轮重新从文本文件创建一个账号 |
| R-04 | 发布中心记录、搜索本系统帖子，并追踪执行、失败、未知结果和核验 | 不默认承诺导入账号在其他渠道发布的全部历史 |
| R-05 | 预设可配置、可版本化、可测试，定义内容边界而非固定文案模板 | 固定句式拼接与仅换币名不构成 AI 独立创作 |
| R-06 | 每账号独立抽样下一次间隔、持久化、重启恢复，按权重选择预设 | 不再使用每15分钟全账号统一发文的批次语义 |

## 对旧要求的继承与调整

| 已有规则 | 新平台中的落点 |
| --- | --- |
| 默认文字模型 `gpt-6-luna`，不可本地套模板替代 | 默认批准模型；平台维护明确的文字模型名单，不允许静默回退到模板 |
| 文字口语自然、避免翻译腔和同质化 | 默认质量规则；预设定义具体语气和观点方向 |
| 正文不能出现“情绪”等元话语 | 沿用用户要求；“情绪”及其派生词作为默认全局正文禁词，规则变更须版本化 |
| 原实现额外拦截的某些正常中文句式 | 重新归为可配置的质量提示，不能把旧实现的每个黑名单自动升级成永久产品需求 |
| 三币、涨跌榜前五、兼顾两榜、三个标签 | “三币行情与新闻”示例预设的内容选择规则 |
| 优先120—190字符、硬上限200字符 | 示例预设的长度规则；平台按预设与远端能力的更严格限制执行 |
| 单张随机图、优先近72小时律动新闻、行情15分钟有效 | 示例预设的素材、数据源和时效规则 |
| 所有账号统一每15分钟发布 | 被账号独立随机间隔取代；原值只可作为迁移时的未启用建议配置 |
| 根目录 `keys.txt`、`imagegen/`、`batches/`、`runs/` | 一次性迁移来源；新平台不继续把批次凭据文件当主数据库 |
| 本地 BAT 双击运行 | 保留为旧本地程序入口；远程平台的常驻运行由服务器服务管理 |

AI 成稿、图片来源和凭据隔离是平台约束；币种数量、文长、数据窗口、新闻偏好和段落规则是预设能力。预设不得覆盖平台约束。

## 首版范围

首版围绕一个所有者、多个本人账号、一个远程部署实例形成闭环：账号 → 预设 → 图库/生图 → 独立调度 → AI 成稿 → 校验 → 发布 → 核验 → 搜索与追溯。

首版不依赖多租户、团队审批、评论点赞、交易下单、私信或视频功能。远端删帖、编辑已发帖子、互动数据统计和全账号历史同步均需要单独验证接口能力，再决定后续范围。

这些范围用于控制本轮需求基线，不代表用户永远不需要相关扩展。
