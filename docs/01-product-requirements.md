# 01 · 产品需求规格

## 产品目标与角色

让使用者在一个 Dashboard 里掌握每个账号“用什么内容规则、何时执行、生成了什么、发到了哪里、失败原因是什么”。实际文字、图片和发送由后端执行并留下可追溯记录。

首版角色为单一所有者管理员和后台工作进程。管理员使用浏览器访问远程服务；工作进程按持久化任务运行，不依赖浏览器保持打开。

## 平台规则

1. 所有实际发送入口使用同一个后端发布关口，定时任务、立即执行、改稿发送均不能绕过 AI 与图片来源校验。
2. 发布关口比较最终文字、图片、事实快照、校验结果与成稿记录的摘要；修改任一发送内容将使旧校验失效。
3. 每次任务最多选择一个绑定预设，使用该版本完成执行；失败重试沿用同一次选择，不反复抽取直到“抽到能发的规则”。
4. 系统按账号独立执行，同时服从服务连接并发、全局并发和远端实际限额。随机时间不提供绕过远端限制的能力。
5. 新账号和新迁移计划默认暂停，管理员启用后按随机间隔安排第一轮。新建预设不会自动替换在途任务。
6. 已确认已发、提交结果不明和已取消的任务不得自动作为新任务再次发送。核验故障不等于发布失败。
7. 预设定义边界与偏好，模型独立组织文章，不引入固定成段文案模板。
8. 平台不能因为单个数据源、文字模型或生图任务不可用而擅自发送替代内容；只有预设明确声明的降级才可采用，并保留记录。

## 状态与可见性

账号可用性、调度是否启用、发布任务阶段、公开核验结果是四组独立状态。Dashboard 应能区分“账号凭据异常”“计划暂停”“任务生成中”“已发但暂未核验”。

所有阻塞展示结构化原因、发生阶段、影响对象、最后错误时间、下一步可做操作；保留去除凭据后的原始响应和请求追踪标识。

## 非功能要求

| 编号 | 要求 | 验收口径 |
| --- | --- | --- |
| N-01 | 远程部署 | 关闭管理员浏览器后，服务仍可继续调度、发送并保存结果 |
| N-02 | 访问与凭据 | Dashboard 有管理员登录；Key 仅经写入接口进入服务端，普通查询返回掩码与引用 |
| N-03 | 状态持久化 | 账号、预设、任务、下一次时间和发布意图在服务重启后不丢失 |
| N-04 | 可追溯 | 能从任一帖子反查账号、预设版本、模型、提示词、输入事实、图片和回执 |
| N-05 | 并发隔离 | 一个账号同一时刻最多一条发布流水线；其他账号可独立执行 |
| N-06 | 时间一致 | 数据库存 UTC；界面默认 Asia/Taipei，明确展示时区；用 UTC 时间计算间隔 |
| N-07 | 可恢复 | 数据库、凭据加密材料和图库具有一致恢复说明，恢复后不会立即补发所有错过轮次 |
| N-08 | 可观察 | 页面展示调度/工作进程心跳、队列、模型耗时、失败阶段和最近成功时间 |
| N-09 | 搜索可用 | 首版支持中文正文连续子串及结构化组合过滤；性能目标待容量信息确认后确定 |
| N-10 | 工程边界 | 新开发在 `app/`，文档在 `docs/`；本地开发不调用 Docker、WSL 等虚拟化环境 |

账号容量、并发值、响应时间和可接受调度延迟需要在服务器与规模明确后测量，不把现有脚本的并发3当作平台容量承诺。
