# 07 · 实施阶段、验收与需求追踪

## 实施方式

先实现可观察和可恢复的单账号闭环，再扩展多账号独立调度。现有模型与广场脚本通过适配器逐步接入；不先将统一批次程序包装成 Dashboard 就认定新平台完成。

所有新增实现与部署配置在 `app/`；文档、验收和决策记录在 `docs/`。真实账号 Key 不进入文档、测试夹具或模型输入。

## 建议阶段

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| M0 · 外部能力与环境确认 | 服务器系统/规模、文字和图片连接能力、广场上传/发布/核验能力、限制与错误分类 | GPT Image 2 实际模型 ID/协议明确，关键接口有验证记录，开发配置无占位未知能力 |
| M1 · 服务与账号基础 | 登录、数据库、账号/Key 管理、模型连接、图库导入、审计、基础 Dashboard | 单账号可管理，Key 掩码正常，历史稳定 ID 与入库来源可追溯 |
| M2 · 预设与 AI 内容 | 多预设、版本、模型成稿证据、图库选择/新生图任务、预览与校验 | 非 AI 文案及非法来源图片均无法经任何发送入口放行 |
| M3 · 发送与核验闭环 | 唯一发布关口、意图/回执、未知结果恢复、帖子列表与搜索 | 单账号可从预览进入实际发送并逐项核验，故障不重复提交 |
| M4 · 多账号独立调度 | 每账号随机范围、多预设权重、互斥租约、启停、重启恢复 | 多账号按独立计划运行，单账号失败隔离、全局暂停生效 |
| M5 · 迁移与远程交付 | 旧凭据/图片/历史迁移、服务部署、备份恢复、运行文档 | 浏览器关闭仍运行；迁移无自动发送，旧新调度切换清楚，全部 P0 验收通过 |

M3 的真实发布测试使用用户明确指定的测试账号和可审阅内容；其他验收优先用适配器模拟与隔离环境。现有发布授权不作为本轮文档工作执行发送的理由。

## 验收案例

| 编号 | 场景与操作 | 预期结果 |
| --- | --- | --- |
| AC-01 | 正常调用批准文字模型生成并发布一篇 | 保存实际提示词、模型/请求记录、最终内容摘要、回执和核验结果 |
| AC-02 | 经手动执行、调度和内部接口提交无 AI 记录的正文 | 所有入口均被统一发布关口阻止，返回明确原因 |
| AC-03 | AI 成稿后手工改一个数字、标签或正文字符 | 旧成稿/校验失效，重新经 AI 后才能发送 |
| AC-04 | 默认模型超时或服务不可用 | 无本地模板或静默其他模型替代；对应任务记录原始错误和有限重试 |
| AC-05 | 图库上传/迁入一张已有图片 | 生成来源、文件摘要和 Asset ID，可以被任务引用并追溯 |
| AC-06 | 创建 GPT Image 2 任务 | 记录正确连接与模型；产物完整入库后才可使用，未完成时不发 |
| AC-07 | 提交任意外部 URL、缺失文件或来源不明图片 | 发布关口拒绝，不会临时用其他来源替换 |
| AC-08 | 创建账号后轮换 Key | 账号 ID、历史和预设不变；新提交使用新版本，查询不回显 Key |
| AC-09 | 导入重复 Key 与新 Key | 重复检测和逐条结果明确，不重复创建同一有效凭据映射 |
| AC-10 | 一个账号凭据认证失败，其他账号正常 | 仅阻塞故障账号，其他账号继续独立执行 |
| AC-11 | 正文、账号、代币、模型、预设和日期组合搜索 | 条件按约定组合，中文关键词可用，分页无重复/漏页且排序稳定 |
| AC-12 | 查看任意已发帖子详情 | 能反查精确正文、图片、成稿记录、预设版本、事实、提交和核验 |
| AC-13 | 发布已确认成功但公开读取暂不可用 | 显示“已发/待核验”，不会自动重发；读取恢复后更新核验 |
| AC-14 | 发布提交后断网、进程中断或回执缺失 | 进入结果不明，先核验，不因用户点击重试而创建重复外部提交 |
| AC-15 | 编辑并发布一个正在使用的预设 | 新任务使用新版本；已认领任务和历史继续指向原版本 |
| AC-16 | 仅测试预设并查看提示词/配图 | 产生可预览任务，无广场发布副作用；显示实际规则、来源和字数 |
| AC-17 | 需要三币行情的预设超长、漏标签或数字对应错误 | 校验拒绝；模型修复后重新验证，不用正则替换后直接发送 |
| AC-18 | 必需数据源失败，另一个预设声明该源可选 | 必需任务阻塞；可选任务按声明省略来源并记录，不能补造事实 |
| AC-19 | 等待生图导致行情失效 | 刷新事实并由模型重新成稿后才能发送 |
| AC-20 | AI 生成正文包含“情绪”及派生词或大量近似历史稿 | 按继承规则和重复策略阻止；修复记录可追溯 |
| AC-21 | 为两个账号设置不一样的上下限 | 分别抽样、保存并展示下一次时间，不在统一批次强制同步发送 |
| AC-22 | 间隔下限大于上限、0、负数或非整数秒 | 保存失败；下限等于上限按固定等待解释 |
| AC-23 | 页面反复刷新与 API 读取同一计划 | `nextDueAt` 和抽样值保持不变 |
| AC-24 | 在可控随机输入下验证多预设2/3/5权重 | 边界选择对应20/30/50理论区间；0权重永不选中，全部0无法启用 |
| AC-25 | 选中预设后取材失败、进行步骤重试 | 同一任务不重新抽预设，不通过反复抽样绕过原规则 |
| AC-26 | 两个工作进程同时认领同账号 | 只有一个活动发布任务；过期执行者提交因租约/版本不符而被拒绝 |
| AC-27 | 单账号任务尚在运行又到期或点击立即执行 | 返回现有活动状态或冲突，不并行发送；其他账号不受影响 |
| AC-28 | 生成期间暂停账号/全局 | 提交前再次拦截；已在外部提交的请求只回收结果，不假称撤回 |
| AC-29 | 服务停机跨过若干次原计划后恢复 | 保留未来有效时间；错过计划分别从恢复时间重新抽样，不补发全部 |
| AC-30 | 关闭浏览器、重启 API/调度/工作进程 | 调度和任务持久存在，服务恢复后遵守未知结果隔离与互斥 |
| AC-31 | 重复点击同一手动动作与幂等键 | 返回同一任务；同键不同参数返回冲突 |
| AC-32 | 迁移旧历史与图库 | 保留来源映射；缺少 AI 证据的历史标明 legacy，不补造证据，不自动重发 |
| AC-33 | 从备份恢复数据库、图库和凭据材料 | 可读取历史和资产；恢复过程保持暂停，核对在途状态后才允许恢复 |
| AC-34 | 查看失败任务详情与运行心跳 | 能看到具体阶段、原始错误、最后心跳和影响范围，日志不包含完整凭据 |

抽样验收使用可控随机源做边界验证，再用足够样本检查统计表现；短期预设出现次数不强求精确等比例。调度延迟与 API 性能目标在容量确定后纳入负载验收。

## 完成定义

全部 P0 功能在远程环境有可验证结果；每个 AC 保存执行方式、输入/配置版本、预期与实际结果、相关任务 ID。真实发布次数与账号由验收计划限制，不靠大量生产帖子代替测试。

交付需包含数据库迁移、部署和恢复步骤、账号/图库/历史迁移报告、API 契约、管理员操作说明，以及未解决的外部能力与容量限制。接口成功、已发和核验通过分别证明，不能相互替代。
