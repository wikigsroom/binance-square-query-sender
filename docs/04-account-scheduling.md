# 04 · 账号独立随机发送调度

## 目标与概念

每个账号分别维护规则、随机抽样结果和下一次到期时间。后端可以共用一个调度服务和工作池，但不能在同一个周期里强制遍历全部账号发布。

“独立定时器”是持久化的账号级逻辑定时器，不要求每个账号创建一个永久线程。浏览器关闭或服务进程重启后，已抽中的时间仍有记录。

## 规则字段

| 字段 | 定义 |
| --- | --- |
| `enabled` | 是否允许产生自动发布任务；全局暂停与账号可用性另外判断 |
| `minIntervalSeconds` | 随机间隔下限，正整数 |
| `maxIntervalSeconds` | 随机间隔上限，整数且大于或等于下限 |
| `nextDueAt` | 已抽中的下一次到期时间，UTC |
| `sampledDelaySeconds` | 本次抽样值，抽中后不随页面刷新变化 |
| `anchorAt` | 本次抽样对应的起点 |
| `scheduleVersion` | 调度规则/控制版本，用于并发更新和认领校验 |
| `controlVersion` | 账号启停、凭据或相关控制变更的版本标记 |

建议首版使用上下限内整数秒均匀抽样。`min=max` 可表达固定间隔，作为随机规则的退化情况；没有对全部账号强制的15分钟周期。

## 间隔起点与任务完成

建议默认采用“上次发布已获确认后的随机等待”，避免一条生成/生图任务耗时过长导致同账号堆积多个待发任务。

成功：`nextDueAt = publishConfirmedAt + U(min, max)`。不等待公开核验结束才安排下一轮，因为已确认发布和公开核验是两个状态。

启用或恢复：`nextDueAt = enabledOrResumedAt + U(min, max)`，默认先等待随机间隔。管理员需要立刻发送时使用单独的立即执行动作。

确定未发布且任务最终失败/被取消：计划仍启用且无阻塞时，从该任务终结时间重新抽取一个正常周期，保留失败记录。暂停或归档的账号不因此被自动恢复。账号存在凭据错误、必需配置缺失或未解决提交结果不明时，先阻塞，不自动进入下一次发送。

步骤重试使用 `retryAt`，不作为新一轮正常抽样。明确可重试的生成/取材步骤复用当前任务；重试次数和退避上限可配置。达到终结条件后再按上段处理。

## 多预设按权重随机

账号绑定集合记为 `(presetId, weight, enabled)`。权重为非负有限数，0不参与；参与选择的权重和必须大于0。

每次到期真正创建任务时，从绑定启用、存在已发布版本且结构上兼容的预设中抽取一次。若权重分别为2、3、5，则长期理论概率分别为20%、30%、50%；短期不保证次数严格匹配。

绑定失效时记录排除原因；没有候选则阻塞账号调度。选中后，记录候选、实际有效权重、随机值、选中项、具体版本和抽样时间。预设因运行中取材失败，不偷偷重新抽另一个预设。

预设绑定默认跟随当前已发布版本；任务创建后不可变。显式修复/重试不重抽预设，新的正常任务才重新抽样。

## 调度认领流程

1. 调度器读取到期且启用、未被阻塞的账号；同时检查全局开关。
2. 在数据库事务里检查版本并认领该账号；同账号只能有一个活动发布任务。
3. 创建唯一任务和执行租约，冻结账号配置、选中预设版本及来源规则；不把完整 Key 放入任务快照。
4. 工作进程逐阶段执行，保持心跳；最终提交前重新检查租约、控制版本、凭据和全局暂停。
5. 发布前保存独立的提交意图，再执行外部调用。成功/失败/结果不明分别持久化。
6. 根据终态安排下一次正常抽样；公开核验使用独立的读取任务。

多个账号可能自然抽中同一个时间，这不违背独立随机。工作池按可用并发执行；队列延迟单独记录，不反向伪造已抽中的到期时间。

## 控制动作语义

| 动作 | 已排定但未执行 | 正在生成或取材 | 已开始提交外部发布 |
| --- | --- | --- | --- |
| 暂停账号/全局暂停 | 保留原计划供审计，停止新发送认领 | 阶段结束后停止，最终提交前必须再次拦截 | 继续收集结果并核验，不能声称撤回已提交请求 |
| 恢复 | 清理失效到期状态，从恢复时间重新抽样 | 若存在活动任务，先解决或终结该任务 | 等待结果明确，不创建重复任务 |
| 修改间隔 | 默认影响下一次抽样；本次时间保持 | 不改变本次已冻结任务 | 不影响已提交内容 |
| 重排下一次 | 从操作时间按新规则抽样并提升版本 | 不抢占活动任务，返回明确冲突 | 返回在途状态，不能制造第二个同账号任务 |
| 修改预设/权重 | 影响新认领任务 | 已认领任务保留预设版本 | 不修改已提交内容 |
| 立即执行一次 | 创建一个带幂等键的手动任务，原未认领计划作废 | 返回活动任务/冲突，不并行发送 | 返回在途任务，不重复提交 |

手动任务确认已发后，从该次确认时间重新抽取下一次正常间隔；手动任务最终未发则从终结时间重排。账号调度原本暂停时，手动任务不自动将其启用。立即执行须显式选择/展示预设；默认仍按账号已绑定权重选择。

“仅暂停自动计划”与“停用账号”分别控制：账号仍可用且只暂停自动计划时，管理员可以显式立即执行一次；停用/归档、凭据异常或结果不明阻塞的账号不能借手动执行绕过。原本暂停的计划不会因一次手动发送而恢复到期时间。

全局暂停期间不能提交新发布，包括立即执行。预览和只读核验可以继续；恢复后各账号分别重新抽样，避免同时补发。

## 重启和停机恢复

数据库保存下一次时间、任务阶段、租约与发布意图。服务重启不逐账号直接“启动即发送”。

- 未来尚未到期的时间继续沿用，不重新抽样。
- 已经过期但从未创建任务的计划默认跳过停机错过轮次，从恢复时刻各自重新抽样，并记录恢复事件。
- 已认领且确认未进入发布提交的任务，在旧租约过期、前任执行者失效后，可按步骤恢复或重新生成；时效过期时重新取材与 AI 成稿。
- 已有发布意图但结果未保存的任务转为 `submission_unknown`，先核验；不自动重放发送请求。
- 已确认已发但核验中断的任务只恢复公开读取，不发送。

租约到期不意味着旧进程停止。提交关口须校验递增的 fencing 标记及账号控制版本；旧工作进程即使完成模型请求，也没有继续提交的资格。

## 故障与限额

| 情况 | 处理 |
| --- | --- |
| 文本模型或来源暂不可用 | 对对应步骤有限退避；不发模板，不影响其他账号 |
| 生图长时间运行 | 记录原任务，查询结果；等待导致事实过期则重做文本 |
| 广场认证明确失败 | 阻塞该账号，提示更新凭据；不无限重试 |
| 限流/配额用尽 | 记录接口反馈，服从可验证的恢复时间；不通过增加 Key 重试相同任务 |
| 提交超时或连接中断 | 标为结果不明，核验后决定；不直接按 HTTP 状态盲目重发 |
| 公开读取暂不可用 | 保持确认已发，按读取退避重核验，不重复发送 |
| 一个账号任务失败 | 只影响该账号本次任务及必要的账号阻塞状态 |

均匀分布的平均等待时间约为 `(min+max)/2`；实际发送间隔还包括生成和排队耗时。该公式用于估算负载，不代表发送配额或严格节奏承诺。

## 调度验收重点

验证独立抽样、边界正确、持久化不漂移、权重选择、配置变化竞态、暂停阻止新提交、重启不补发风暴、未知结果不重发，以及同账号互斥。具体案例见 [07](07-delivery-and-acceptance.md)。
