# 正文混入梗图脚本：排查与修复

检查时间：2026-10-23 05:14，Asia/Taipei。用户指出的正文以“行业梗图：一只戴工牌的河狸策划”开头，是不应混入文章的配图脚本。

## 已核实的原因与范围

该帖在 2026-10-23 05:09:19（台北时间）发布。对照平台帖子正文和原始 `gpt-6-luna` 响应，解析响应 JSON 后的 `text` 与已发布正文完全一致。不是程序在发送时另外拼接了这段话，而是文字模型生成的正文已经包含画面脚本。

此前作者和校对请求都直接使用 `rules: job.rules`，把 `rules.image.prompt`、风格、图片标签等生图配置一并传给文字模型。2026-10-22 修改行业梗图策略后，这些要求进入写作上下文；文字模型把“画一只动物打工”也理解为正文任务。系统提示没有明确划定文章正文与独立图片任务的边界。

同一请求的40篇历史参考中已有33篇含梗图描述。这些错误文章又被当作历史参考送回模型，放大了重复叙事。该段出现了松鼠、企鹅、水獭、河狸、海龟等变体，但“资产流通流程图—奖励领完—回头客理由”的叙事基本相同。

检查最近100篇平台发布记录，66篇含“行业梗图”“梗图：”“配图：”等明显画面描述标记。此数值是检查时的文本标记统计，不代表完成了所有历史帖子的人工内容审查。

生产当时使用 `publish_first`。内容风格问题不会阻止发送，因而这些正文通过发布流程。修复重点是模型收到的任务输入，而非重新收紧全部内容校验。

## 实现调整

- [writing-context.ts](../app/square-service/src/writing-context.ts)通过明确的文字字段清单构造作者和校对上下文，保留文字方向、语气、篇幅、币种、来源和材料等。图片配置、未来新增的图片字段及模型传输参数不进入写作规则。
- 写作提示词升级为 `square-author/1.3.0`，明确仅输出完整文章正文，图片由独立任务处理；不把配图说明、梗图脚本、生图提示词、分镜或画面创意写入正文。幽默、自嘲和普通比喻仍可用于文章。
- 校对提示词升级为 `square-review/1.1.0`，采用同一文字上下文隔离。
- 送给文字模型的历史参考排除有明显画面脚本标记的整篇示例。原始帖子、模型响应及审计记录保留，不修改或截断成稿；历史相似度校验仍可使用原始历史。
- 图片任务继续独立读取完整图片配置，执行 `industry-meme-v1` 行业梗图策略。隔离对已有冻结预设任务生效，无需覆盖预设、绑定或随机计划。
